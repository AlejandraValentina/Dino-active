## Method

Evaluate an engine-knowledgeable first-time user through 2T, native 4T and
4T 0D reference workflows. Observe the actual source GUI, mouse/keyboard actions,
screenshots and state inventories. Isolate settings, projects and artifacts.
Record source-assisted fixture loading separately from visible interactions.
Use existing results or tightly bounded engineering runs; do not claim scientific
validation or manufacture a successful result. Label unexercised paths.

Cover navigation, motor editing, execution and RPM curves, results/comparisons,
project lifecycle, visual consistency, compact layouts, keyboard and error states.
Distinguish a demonstrated defect, a usability inference and a proposed capability.

## Deliverables / acceptance

1. Revision-bound methodology, route matrix and evidence index with limitations.
2. Diagnosis: ID, location, category, impact, evidence and probable cause.
   Categories: confusion, discoverability, incomplete flow, inconsistency,
   visualization, missing capability and functional defect.
3. Concrete information architecture and visual wireframes of the main flows.
4. P0/P1/P2/P3 backlog with expected outcome, affected components, dependencies,
   acceptance, verification and frontend versus application-backend responsibility.
5. Critical evolution versus reorganization decision, migration/compatibility
   strategy and self-review. Do not label the author's review independent.

An audit-deliverable PASS accepts research/design delivery only, never the
current product, future implementation or scientific correctness.
