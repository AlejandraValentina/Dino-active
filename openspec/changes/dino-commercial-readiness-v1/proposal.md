# DINO Commercial Readiness V1

## Why

The current Windows application has a capable integrated solver, engine and exhaust editors, projects, variants, execution and analysis. Its `Nuevo proyecto` action still creates a project from a historical synthetic fixture, so a new user cannot start from a clearly identified blank design and complete the requested build–run–modify–compare journey without knowing the fixture's provenance.

## Scope

Reuse the current Qt Desktop, engine configuration adapter, project store, execution coordinator, result importer and comparison views. Make `Nuevo proyecto` open a guided design form with visibly assumption-labeled starter values and no attached historical runs. Preserve provenance for measured, estimated and assumed inputs. Complete only editor and analysis connections required for a Windows user to create a design, run a bounded exploratory integrated point, modify exhaust geometry, and compare the saved variants. Build and demonstrate the resulting Windows TRIAL package from a new project.

## Non-goals

- No solver equations, physical models, historical evidence, frozen contracts, periodicity criteria or X30 configuration changes.
- No new multicylinder, turbocharger, optimizer, broad verification campaign or replacement desktop application.
- No commercial validation claim. Experimental validation remains pending.
- No manual editing of JSON, scripts or databases in the acceptance workflow.
- No push.

## Authority

The user explicitly requested implementation and a Windows demonstration in the session dated 2026-10-23. This change supersedes the completed packaging objective only for the new-project design workflow and its acceptance demonstration.
