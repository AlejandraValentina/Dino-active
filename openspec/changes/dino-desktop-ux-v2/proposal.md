# DINO_DESKTOP_UX_V2

## Why

The current Windows Qt application exposes useful engineering controls but the project and active variant are not persistent context, historical results can be confused with current project output, run selection is file-oriented, and several pages clip or overlap at common window sizes. The attached Opus proposal documents the inspection findings and design direction.

## Scope

Redesign the existing desktop application around projects and variants. Implement the authorized P0/P1/P2 UX, run history and direct comparisons, clear exploratory-run expectations, responsive engineering forms, status presentation, preference persistence, visual/functional verification, and a Windows TRIAL package.

## Non-goals

- Solver, physics, mesh-adapter, hard-gate, periodicity-contract, preregistration, or scientific result changes.
- New exhaust diagnostics, RPM campaigns, KT100, or verified-mode activation.
- Promotion or reopening of EXHAUST_NUMERICAL_CONVERGENCE_V2_PARTIAL.
- Persistent audit-cache semantics, mass-run confirmation, or automatic propagation from base engine to existing variants.
- P3 drag editing or generalized undo/redo unless a narrowly justified safe implementation is found.
