# DINO_TUNING_WORKBENCH_V1

## Problem

The existing desktop is oriented around separate audit and configuration pages. The owner authorized a unified two-stroke engineering workbench based on the archived `DINO_COMMERCIAL_UX_BENCHMARK_PROPOSAL`. The reference archive and its provenance are stored under `docs/dino_tuning_workbench_v1/reference/`. The proposal's commercial-product observations retain their original source labels and evidence limits.

## Scope

Correct measured desktop defects D1-D8; present motor, ports, exhaust, combustion, execution and available results in one coordinated workspace; show explicit baseline and engineering diffs; keep scientific evidence accessible in an advanced evidence drawer; improve exact, discrete pressure/flow/wave comparisons. Provide a verified source and Windows TRIAL workflow.

## Non-goals

No solver, physics, mesh, periodicity, hard-gate, preregistration, output, or historical-artifact changes. No RPM campaign, multi-run queue, batch confirmation, automatic budget increase, degree-to-millimeter inverse editing, empirical tuning advice, or scientific/experimental claim. Each run still requires individual confirmation and backend fail-closed behavior remains intact.

## Acceptance

The named 180-to-200 mm escape scenario must remain in a single engineering workspace, make the changed section and active variant unmistakable, support explicit baseline selection and existing-run comparison, and expose transients and evidence without fabricating performance. The workflow should need at most 12 principal actions and two principal focus changes. It must be tested at 1360x900 and 980x680; Windows DPI scaling is reported only when actually tested.
