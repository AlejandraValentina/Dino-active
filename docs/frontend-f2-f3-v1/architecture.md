# F2/F3 architecture

Main consolidated by fast-forward to97e40bd; receipt records parent and rc13 archive hash. Development isolated, CP3/CP4 owned separately.

Presentation adapters map existing public configuration sections into component routes; widgets never instantiate solvers. A component schematic is topological, never a CAD or dimensional reconstruction. Selection has an equivalent keyboard control and routes to existing forms; applied values and drafts retain F0 guards.

CurvePlot is the shared single-axis real-sample renderer. FourStrokeCurve adapts its existing tuple contract; no scientific interpolation or eligibility logic is added. Viewport state changes rendering only, cursor chooses existing samples. Existing dual-axis2T view keeps its units and eligibility; detailed exploration can expose single-axis metrics without changing scientific contracts. Exports identify source and missing values.

Application commands own external binding, recovery-copy selection and variants. They use existing readers/context mutations, retain identities and history, and never promote legacy or synthetic evidence. Generalized durable jobs are explicitly capability scoped; no claim of universal checkpoint restart.

Design references: Qt keyboard focus and accessibility (https://doc.qt.io/qt-6/focus.html and https://doc.qt.io/qt-6/accessible.html); ParaView data selection with linked chart elements (https://docs.paraview.org/en/v5.9.1/UsersGuide/selectingData.html). Adopt explicit selection plus tabular values, native focus and keyboard alternatives. This is a design inference, not a claim of equivalent engineering capability.

Delivery: linked components; charts; variants/results/recovery; compact navigation; combined application acceptance; one grouped Windows candidate;23finding review. Each increment carries tests and durable queue state.
