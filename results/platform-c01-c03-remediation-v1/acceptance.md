## C01 criteria

1. A section-aware native config validation contract rejects malformed object
   types, booleans used as numbers, nonfinite values, invalid integer domains,
   nested unknown controls and invalid model selectors before any simulation.
   No float-to-int coercion or silent key/default fallback. Known valid configs
   keep their exact numeric values and canonical identity. Errors are data.
2. Detector validation rejects invalid tolerance/count domains; the status and
   actual convergence decision use the same positive count, minimum-cycle and
   finite-metric conditions. Default thresholds, comparison <= semantics and
   valid integration steps remain unchanged. Zero-cycle incomplete is valid;
   it cannot be a periodic success. Historical periodic classifications are
   not rewritten.
3. A versioned result assessment checks types/finiteness, cycle/status/
   termination/history agreement and recomputes streak from numerical metrics,
   not a stored passed flag. With resolved config it binds config identity,
   exact operating point, actual model selections and detector settings.
   Unsupported measured/predictive claims remain unverified even if an
   arbitrary evidence object exists. Valid original A/B endpoints stay valid.
4. Signed finite friction coefficients are not universally invalid. The
   evaluated FMEP must be finite and nonnegative and consistent with net IMEP
   and BMEP. A negative evaluated loss makes the result ineligible; preserve
   the original calculated data, do not clip or refit it. No invented
   correlation-validity rectangle or new calibration policy.
5. Positive presentation fixtures must be made internally consistent with the
   strengthened contract; record those fixture changes. No protected P0–P9
   expectation, tolerance, evidence or scientific result is changed.

## C03 criteria

1. Producer-created artifact manifests bind exact raw summary/config/trace
   bytes, config semantic identity and original metadata. A manifest digest
   is anchored in a versioned outer run reference. Computing a new digest
   beside a mutable file is not original provenance. Avoid hash cycles.
2. Readers use a verified immutable byte snapshot for graphs and recheck
   current source integrity for comparison/export. Trace replacement,
   metadata redirection, mixed endpoints and source changes fail closed.
3. Old data lacking original bindings remain retained and explicitly
   LEGACY_UNVERIFIED, not silently promoted. An explicit reconstruction from
   an independently supplied original receipt may copy exact bytes into a
   new bundle with its reconstruction provenance. Originals/hashes never change.
4. New bundles use safe relative paths, fixed byte/serialization policy and
   no-overwrite publication. Moving a project with its bundle preserves
   identities without its original source checkout. Cross-EOL import does not
   silently normalize hash-bound historical bytes; any reconstruction is explicit.
5. One complete declaration drives consumed repository/data inputs in spec,
   manifest and dirty guard, plus explicit external optional inputs. Missing,
   changed, added, deleted or swapped inputs cannot be called clean. Preserve
   raw consumed preimages and generated/external distinctions.
6. Source provenance covers shared runtime code/data dependencies, hashes its
   full inventory and fails to INCOMPLETE/unknown if Git or required preimages
   cannot be verified. Package clean identity requires complete embedded and
   verified preimages, not legacy flags alone. Native and legacy 4T models are
   explicitly distinguished in build metadata.
